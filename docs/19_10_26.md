# 19 Oct 2026

What landed on 18 and 19 October 2026.

The 18 October work and the workspace-creation fix are on `main`. The rest of 19 October (Ask data tools, the colour scheme, and Slack) is in the working tree and has not been committed, so a Railway deploy of `main` does not include it yet.

## 18 October

### Guided workflows

Loom Capture can walk someone through an approved Skill File instead of only recording a new one.

- Each step can carry an anchor: the app, the control, and the window it belongs to.
- The Mac app matches those anchors while the person works and advances the step when the action happens. The Workflows page shows how many steps can auto-detect, for example `4/6 steps auto-detect`.
- A guide overlay and a guide library were added to the desktop agent. The capture API stores the guide steps with the Skill File.

### Import page and Loom Capture install

- Connected apps stay on the Import page. Everything else sits behind **Add connector**, which opens the list of Google Workspace, Microsoft 365, Zoom, and GitHub.
- The separate WhatsApp filter is gone. Dropping a chat export on the upload box still imports it.
- The Loom Capture zip download is hidden. Install is the Terminal command only, because macOS was blocking the unsigned zip.
- **End** in Loom Capture ignores extra clicks while the session is uploading. The button and the menu both read **Processing Skill File…** until the Skill File draft is done.

## 19 October

### Asking and creating workspaces

Creating a workspace was failing with a 400 because some models reject `reasoning_effort`. The API now drops a parameter a model refuses, remembers that for the model, and retries the request. The same treatment covers other parameters those models reject, such as `temperature`.

Ask can answer questions that need a live lookup, not only a search of stored chunks:

- **How many emails did I get** counts Gmail or Outlook mail the signed-in person is allowed to read.
- **What is the status of project tiramisu** reads the status board and the knowledge graph.
- **How many Slack threads** is included once Slack content has been ingested.
- People named in a workspace request who are not in the directory are reported back instead of being saved with an empty user id.

### Slack Loombot

An admin connects one Slack app per organization from **Import → Add connector → Slack**. MindLoom generates a manifest; the admin creates the app in Slack from it and pastes the bot token and signing secret. There is no shared “Add to Slack” app yet.

- `@Loombot` is answered in the thread with the same Ask path as the site. The sender is matched by email, so the reply only includes what that person can already see. People without a MindLoom account are ignored, or answered from organization-wide knowledge only, depending on the admin’s setting.
- Chosen channels, and threads that mention Loombot, are saved about once a minute. A thread is one document, visible to the channel’s members. Loombot’s own messages are not saved.
- A drafted email, workspace, or pull request cannot be approved in Slack. The reply points the person at the Ask tab.
- Slack must be able to reach the API. Set `PUBLIC_API_URL` to the API’s public HTTPS address (the Railway API domain, or a tunnel locally). `http://localhost:8000` cannot receive events. The setup wizard warns when the URL is localhost or not HTTPS.
